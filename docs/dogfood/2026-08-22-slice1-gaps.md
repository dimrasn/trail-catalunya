# Dogfood — taste Slice 1 (2026-08-22)

Roadmap Step 4 gap list. Round 1 = a cold-agent dogfood (Claude planning over the
live MCP only, no training connector). Scenario: *"a scenic September trail near
Barcelona, 15–25 km, not too technical, worth the drive."* Each finding tagged
**fix-now / enrich / park**. Dima's real dogfood (his Claude + Strava, the
composition bet) appends here as round 2.

## What worked
- search_races → drive time + difficulty + a taste one-liner is a genuinely good
  shortlist shape. **Cursa de la Vinya i el Pàmpol** is the proof the bet works:
  from taste alone an agent correctly reads it as scenic (vineyard wine country,
  Montserrat on the horizon) and not-technical ("the challenge is heat, not
  terrain") — the exact discrimination the query wanted.
- get_race full taste with claim-strength labels reads cleanly; Organizer vs Our
  read vs Derived is legible.

## Gaps (ranked)

1. **[fix-now] taste isn't queryable, only inspectable — the core limit.**
   The differentiated axes (scenic, technical, night, food) live in taste and
   can't drive search_races; the agent must get_race every candidate to filter on
   "not too technical". For a taste-first discovery layer this is THE gap.
   Options: (a) carry a few key character flags (night, technicality band,
   scenic) into the list projection so an agent filters client-side without N
   get_race calls; (b) add taste-derived filters to search_races. Biggest
   agent-experience lever — candidate for Slice 2 / Step 3.

2. **[fix-now] taste_available=True but empty taste_summary.**
   Races with character but no `unique`/`reference_point` editorial (Murtrail,
   Espintrail Vertical, Cursa del Margalló, Cursa el Pont de Vilomara this run)
   show `taste_available=True` with a blank summary — a list agent can't
   discriminate them or know a get_race is worth it. Fix: `tasteSummary` should
   fall back who → catch → setting so every taste-bearing race has a one-liner.

3. **[enrich] technicality coverage is sparse.**
   Absent on 2 of 3 inspected (Burriac Atac, Cursa de la Vinya). Since "not too
   technical" is a core axis, thin technicality means the agent can't reliably
   honor it. Prioritize technicality in the enrichment salvage.

4. **[fix-now] Burriac Atac runner overrides not merged.**
   Dima's `_overrides/burriac-atac.md` (near-technical descents, no cups, headlamp
   check, start≠finish, best start package) is NOT in live taste — so the agent
   sees no technicality signal on a race Dima knows is technical, and could wrongly
   recommend it as "not too technical." Merging overrides is a Slice-2 item; do it.

5. **[park→your dogfood] readiness / composition untested.**
   The readiness + projected-time path needs a Strava/Garmin MCP; without one the
   instructions correctly tell the user to connect it. Only testable in Dima's real
   Claude with Strava connected — that's round 2 and the north-star bet.

6. **[park] N+1 pattern.** Planning over taste = 1 search + N get_race. Fine at
   this scale; finding #1(a) would reduce it.
